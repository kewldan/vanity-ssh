# vanity-ssh

GPU (Metal) search for Ed25519 OpenSSH keys whose `SHA256:` fingerprint matches a pattern.
macOS 13+, Swift 6 package, one self-contained binary.

## Commands

- `make test` — all tests. GPU tests compare every GPU digest with CryptoKit; they are skipped
  when no Metal device exists (CI runners may lack one), so run them locally after GPU changes.
- `make lint` — `swift format lint --strict`, `clang-format` (Google style) on the Metal file, and
  a check that the embedded kernel is up to date. CI runs exactly this.
- `make format` — apply formatting and regenerate `KernelSource.swift`.
- `swift build -c release && .build/release/vanity-ssh --benchmark` — measure keys/s.

## Layout

- `Sources/VanitySSH/Metal/Kernel.metal` — all GPU code: field arithmetic (10 limbs, radix
  2^25.5), Edwards point ops, SHA-512/SHA-256 for the fixed input sizes, table building, search.
  Excluded from the target; it reaches the binary through `KernelSource.swift`.
- `Sources/VanitySSH/KernelSource.swift` — generated by `scripts/embed-kernel.sh`. Never edit.
- `GPUSearcher.swift` — compiles the kernel with `WBITS` / `KEYS_PER_THREAD` macros, builds the
  fixed-base table on the GPU, runs batches (two in flight), re-checks matches with CryptoKit.
- `Pattern.swift` — pattern → per-character masks of allowed base64 values, match positions,
  probability. `Ed25519Key.swift` / `OpenSSHKeyFile.swift` — CPU derivation (CryptoKit) and the
  unencrypted `openssh-key-v1` writer.
- `Sources/vanity-ssh/` — the CLI (swift-argument-parser). Results on stdout, everything else on
  stderr.

## Rules

- Never print, log or otherwise expose a seed or private key. Only the 0600 key file holds it.
- Keys must stay standard: seed → SHA-512 → clamp → scalar × B, as RFC 8032 and OpenSSH do. Don't
  add shortcuts (e.g. incrementing scalars) that produce keys without a seed.
- Any change to the kernel or to seed derivation needs `make test` to pass on a Mac with a GPU.
- Metal is compiled at runtime with MSL 3.0 (macOS 13): no lambdas; use functor structs.
- After editing `Kernel.metal`, run `scripts/embed-kernel.sh`.
- Keep the CLI's progress and messages on stderr so `vanity-ssh ... > fp.txt` captures only the
  fingerprint.

## Style

- Swift: swift-format with `.swift-format` (2 spaces, 100 columns).
- Metal: Google C++ style via `.clang-format` — `PascalCase` functions and types, `snake_case`
  variables, `kName` constants, 80 columns.
- Conventional Commits (`feat:`, `fix:`, `docs:`, `ci:`, `chore:` …), committed straight to `main`.

## Releases

Bump `VanitySSH.version` in `Sources/VanitySSH/Version.swift`, commit, then tag `vX.Y.Z` and push
the tag. `.github/workflows/release.yml` checks the tag against the version, runs the tests,
builds a universal binary and publishes the archive with a SHA-256 checksum.
